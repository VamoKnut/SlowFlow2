# Implementation phases

Implementation follows Section 34 of the requirement specification. A phase
must build and test before work starts on the next phase.

| Phase | Scope | Status |
| --- | --- | --- |
| 1 | Repository, solution, terminology, PlatformIO/VS Code tooling, GitHub baseline | Complete |
| 2 | Domain model, EF Core mappings, Identity, initial migration | Not started |
| 3 | MQTT protocol DTOs and transport | Not started |
| 4 | Boot, status, telemetry, alarms, idempotent ingestion | Not started |
| 5 | Desired state, commands, outbox, acknowledgements | Not started |
| 6 | Shield, analog and Modbus sensors, storage, actuator foundation | Not started |
| 7 | Firmware control modes and local control | Not started |
| 8 | Compact operational web UI | Not started |
| 9 | Integration and Automation APIs | Not started |
| 10 | Geometry and hydraulic calculations | Not started |
| 11 | Calibration and configuration management | Not started |
| 12 | Remote temperature integrations | Not started |
| 13 | Public insight pages | Not started |
| 14 | OTA technical prototype and implementation selection | Not started |
| 15 | Operational hardening, backup, deployment verification | Not started |
